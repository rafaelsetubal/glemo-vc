DATA ROOM SECURITY

Data Room Security and Access Plan

Demo access is different from investor-grade production access.

This note separates the current static investor pack from the controls required before sensitive diligence files are hosted for external investor review.

Current State

The current package is a controlled demo/static data room. It is appropriate for curated sharing and local review, but it should not be treated as a production-secure investor portal for sensitive documents without additional server-side controls.

Production Controls Required

ControlRequirementInvestor benefit
Individual accessUnique login or expiring link per investor, fund, counsel or advisor.Shows discipline and protects confidential materials.
Access logsTrack user, document, time, IP/device and download activity.Allows follow-up based on real diligence behavior.
File-level permissionsSeparate public teaser, deck, pre-NDA and post-NDA files.Reduces accidental disclosure and improves diligence sequencing.
WatermarkingWatermark sensitive PDFs with recipient, date and confidentiality legend.Creates accountability for confidential circulation.
Version registerEvery shared file has a version, date, owner and replacement status.Prevents old documents from conflicting with current thesis.
RevocationAbility to revoke a specific investor link or account without affecting others.Protects the company if a process changes.

Sharing Rule

The investor-facing package should include PDF, HTML and XLSX materials needed for diligence. Editable deck files should remain outside the public upload package and be shared only when specifically requested by a trusted party.

Next Implementation Step

The next production data room should move from static password behavior to server-side authentication, per-investor access, audit logging and a clean document version register. The current V4.7 product package and v2.3 diligence package should be treated as the clean content baseline for that implementation.
