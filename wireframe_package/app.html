MVP1 Feasible Scope

A practical first release that proves the liquidity and distribution thesis without trying to build the entire financial infrastructure on day one.

MVP1 Operating PrincipleBuild the minimum credible platform for buyer discovery, seller onboarding, asset publication, controlled diligence, basic revenue and transaction proof. Keep heavy integrations modular.
Build nowCommercial marketplace and buyer eligibility.

Investors must understand the asset, risk, route and next step before talking to anyone.

Build nowSeller asset submission and fact sheet.

Originators need a real path to submit assets, evidence, rules and distribution channels.

Manual nowAdmin clearance and compliance queue.

Manual review is acceptable in beta if every decision has status, owner and evidence.

LaterOpen dApp economy and deeper automation.

Plugins, extensions and automated rails should scale after the core liquidity loop is proven.

Build first, expand with proof

MVP1 should prove that GlemO can source tokenized assets, make them understandable, qualify buyers and record transactions.

The first viable version should not depend on a fully automated exchange, complex custody stack or open dApp economy. Those can be integrated progressively after GlemO proves demand, supply, reporting discipline and paid enterprise usage.

1. SupplySeller account, KYB and asset submission.
2. DiligenceAsset sheet, documents and validator gate.
3. DemandMarketplace, retail login and institutional leads.
4. MonetizeEnterprise AI, billing and transaction fee tracking.
5. ProvePrivate records, public declarations and reports.

Risk and Token Reference Engine

Parameters governing offering structure, risk classification, investor eligibility, material event blockers and daily token reference value.

Token Rule and Risk HubRisk, eligibility, liquidity policy and reference value rules connect investor access to operational controls.

Generic Token Reference Formula

For pools: P(t) = NAV(t) / Tokens(t), where NAV is calculated from outstanding principal, accrued interest, expected losses, prepayments, liquidity reserve, fees and validated material events. For standalone assets: P(t) follows the asset issuance rules, predefined supply, unit value and validated economic events. In both cases, reference value is based on fundamentals and written rules, not speculative buy/sell pressure.

Pool Structure

Multiple contracts form one offering. NAV, LMO, replacement and portfolio risk drive the daily reference value.

Standalone Asset Structure

One tokenized asset or instrument is offered with predefined quantity, value per asset and rule set. The detailed rules will be written by the originator and validated before publication.

Decision 4: Floating Environment Switcher Pattern

Resolution: High-level context switching happens via a compact, accessible floating controller on the bottom-right. This completely decouples global workspace switching from horizontal topbar clutter and prevents sidebar duplication.
