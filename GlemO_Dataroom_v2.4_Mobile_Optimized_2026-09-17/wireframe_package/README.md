# GlemO RWA Product Readiness Platform Prototype V4.7

This package contains the current GlemO product-readiness platform prototype for diligence and product review. It is an illustrative beta artifact, not production software, not an investment offer and not a final regulatory implementation.

## Open the Prototype

Open `index.html` first.

Recommended navigation:

- Start with `MVP1 Scope` to understand what is feasible in the first release.
- Open `Journey Map` to see all actor environments and platform routes.
- Open `DFD & Requirements` to see the current data flow diagrams, product requirements and traceability to screens, actors, data stores and controls.
- Open `Readiness Register` to see the required artifacts, controls and owner responsibilities for each actor.
- Continue through Marketplace, Retail Portal, Institutional Portal, Seller Admin, Asset Factory, Validator Desk, Admin Dashboard, Billing, AI Ops, Rails, Ledger and Downloads.

The legacy `prototype/index.html` route now redirects to `app.html` so there is only one current platform version inside the package.

## MVP1 Operating Rules

- No secondary market is assumed in MVP1.
- Sensitive transactions can enter an admin standby queue before execution or public declaration.
- Sellers and originators should receive pre-check feedback before admin review.
- Assets only become visible after evidence review, validator opinion and admin publication.
- Investor access depends on KYC/KYB, suitability, jurisdiction, offering rules and risk profile.
- Token behavior remains an ecosystem and contribution mechanism. It is not the investment thesis.
- Ethereum and Base are the initial EVM-aligned rails for technical and ecosystem positioning.

## Preserved Business Rules

- GlemO is positioned as an asset-class-neutral liquidity and distribution rail for tokenized real-world assets, with real estate credit as the first proof market.
- Banks and financial institutions can be originators, partners or clients, but GlemO does not need to become the bank, issuer, custodian, exchange or market maker.
- Liquidity obligations belong to the approved originator/client or designated liquidity provider under the offering rules.
- Token reference value is based on asset fundamentals and written offering rules, not speculative trading.
- Standalone assets and pools can have different redemption, lockup, disclosure and amendment rules.
